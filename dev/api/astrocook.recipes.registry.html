astrocook.recipes.registry module#

The recipe registry: the single description of every recipe.

Each recipe module defines its recipes in a *_RECIPES_SCHEMAS dictionary (its brief and details, its parameters with their types, defaults and descriptions, and its flags). The registry reads them once, at import, into frozen RecipeSpec and ParamSpec objects; the GUI (menus, dialogs, requirements, branching), the scripts and the MCP server read the registry, never the dictionaries, so that a recipe is described in one place and nothing changes its description at run time (findings register F12 and F79; ROADMAP.md, phase 6-bis).

Adding a recipe means adding its entry to the dictionary of its module (and its method to the recipe class): tests/test_recipe_registry.py checks that the two agree.

Keys of a recipe entry:

brief

One line, the name of the recipe in the menus and dialogs.

details

A longer description (optional).

url

The page of the documentation (optional).

params

The list of the parameters (keys below).

gui_hidden

The recipe is not in the menus (it is run by the GUI or by scripts).

branching

The recipe opens a new session (or several) instead of giving the next state of the same session.

requires

What the recipe needs from the session before it runs: "z_em", "resolution", "continuum" (astrocook.recipes.prerequisites says what is missing and fills it).

provides

What the recipe gives to the session, among the same names (e.g. estimate_auto the continuum): the recipes named to the user when a prerequisite is missing.

methods

What the recipe did, as a sentence of the methods section of a paper (astrocook.methods_text, phase 6-ter PR 5c): a template with the parameters as fields ({kappa}) and {menu} where the menu of the recipe goes, or a function of the same values that returns the text, when the text depends on them.

references

The keys of the works the text of methods cites, in astrocook.methods_text.REFERENCES.

Keys of a parameter: name, type, default, doc (optional, the name if missing), gui_hidden (not shown in the dialog), and for the conversion of its value (astrocook.recipes.params): optional (None is a value: no value, or automatic), keep (special strings passed as they are, e.g. '_current_'), min and max (bounds of a number, included), gt (a bound excluded: the value must be above it), allow_nan (NaN is a value; infinities never are), choices (the values allowed, for a string: a list in the GUI and for the agents), kind (what a string names: 'session', an open session, 'sessions', several, comma-separated (phase 6-quater, PR 9: the rule of both in astrocook.recipes._sessions), or 'column', a column of the spectrum; phase 6-bis, PR 6c), agents (False: not offered to agents, which get the default: the options of debug and the questions of the GUI, phase 6-bis, PR 6; every recipe is offered, Guido: the basic ones are blocks of new recipes), aliases (the old names of a parameter that was renamed, below).

A renamed parameter keeps its old names as aliases (phase 6-quater, PR 2, agreed with Guido): the logs saved in the archives, the scripts and the calls of the MCP tools that use an old name still run, and give the same result. RecipeSpec.canonical() turns the old names into the new one; it is called where the parameters enter a recipe (the decorator typed_recipe), where the log records them (resolve_params), by the MCP server before it refuses the unknown parameters, and when the log of an archive is read (canonical_params()), so that the methods text, the Log Scripter and the log of the MCP server show the new names only. The dialogs and the schemas of the MCP tools show the new name only. An alias is silent (no warning) and permanent: the archives are not changed once saved, and their logs must replay; an old name given with the new one is an error (InvalidParameter), even with the same value. An alias is not in the signature of the method.

A parameter without a default (required: the method has none, the dialog starts empty, the MCP schema lists it in required) has the default "" (a string) or None without optional (a number, a bool, a list; phase 6-quater, PR 10).
