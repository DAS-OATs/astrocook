class astrocook.core.structures.SessionMetadataV2(constraints_by_uuid: Dict[str, ~typing.Dict[str, ~typing.Any]]=<factory>, v1_reconstruction_data: Any = None, log_history_json: Any = <factory>, log_type: str = 'v1_legacy', component_uuids: List[str] = <factory>, astrocook_version: str | None = None)[source]#

Bases: object

Core immutable structure for holding constraints, configuration, and history.

This structure is designed to be serialized to a JSON or YAML file within the .acs archive. It separates the lightweight metadata from the heavy spectral arrays.

Parameters:

  • constraints_by_uuid (dict) – A mapping of Component UUIDs to constraint dictionaries.

  • v1_reconstruction_data (Any) – Legacy data structure preserved for technical debt logging or V1 reconstruction.

  • log_history_json (Any) – The serialized log object (either a V2 dict or V1 JSON format).

  • log_type (str) – Type of log stored: 'v2' (the only one read back), or 'unknown' when the session had no log. Older archives may carry 'v1_artifact' (a wrapper of V1 logs that was never created, removed in phase 6) or 'v1_legacy': their log is not restored. Defaults to 'v1_legacy'.

  • component_uuids (list of str) – An ordered list of all component UUIDs in the session.

  • astrocook_version (str or None) – The version of Astrocook that saved the archive; None for archives saved by versions up to 2.0.3, which did not record it (findings register F45).

A note in the V2 analysis log: text that is not a state change (e.g. what an agent did outside the recipes), skipped by the replay.

The notes are kept apart from the entries, so that the entries stay 1-to-1 with the states of the history, and the logs saved with notes replay in the versions before them, which ignore the notes (phase 6-ter, PR 5a).

class astrocook.core.structures.HistoryLogV2[source]#

Bases: object

Manages the linear history of operations (Log V2).

This class maintains a list of LogEntryV2 objects matching the stack of immutable states in the session manager. It supports truncation to handle branching history (undo/redo logic).

__init__()[source]#
entries: List[LogEntryV2]#

The list of operations performed (list of LogEntryV2).

current_index: int#

Pointer to the currently active log entry (state), i.e. the last valid entry.

notes: List[LogNoteV2]#

The notes (list of LogNoteV2), in the order they were written; those written after an entry undone are undone with it.

previous: HistoryLogV2 | None#

The log of the archive the session was opened from (a HistoryLogV2), or None: read only, shown while the session is open, never replayed nor saved again (F109: each saved archive is a node, its log goes from its original data to its state; see opened_from()).

property is_v2_log: bool#

Return True, indicating this is a V2-native log structure.

classmethod opened_from(archive_log: HistoryLogV2 | None) → HistoryLogV2[source]#

The log of a session opened from an archive: empty, with the log of the archive as previous.

The rule of the sessions (F109): each saved archive is a node, with its original data (A, the *_orig members), its state (B) and the log from A to B. When it is opened, B becomes the new A and the log starts anew; the log of the archive is kept only to be read while the session is open. Its own previous log is not kept: the logs of the earlier nodes are in their archives.
